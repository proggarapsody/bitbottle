# Критичный QA-профиль текущего выпуска

**Решение:** 2026-10-19. **Статус:** локальный gate Stage 2 прошёл на
предыдущем снимке исходников. После усиления проверки неизменности профиля
нужен повторный полный прогон; текущий выпуск остаётся **NOT READY**, пока не
получены доказательства на финальном SHA и не пройдены остальные release gates.

**Локальный прогон до усиления gate:** полный hermetic `./...` завершился с кодом 0;
`make qa-critical-check` подтвердил **125/125** выбранных provider-строк и
**17/17** обязательных публичных тестов с четырьмя указанными ниже
исключениями. 35 Python-тестов runner прошли. Сохранённое доказательство:
`/tmp/bitbottle-critical-release-20261019/` (`report.md`, `report.json`,
`test-events.jsonl`, `run.json`, `run.sha256`). В том же новом отчёте полный
каталог имеет **123/1165** полных строк и **1042** незавершённые строки.
Это проверка прежнего снимка исходников, не проверка обновлённого gate, не CI
финального SHA и не live проверка provider или бинаря-кандидата.

[`test/qamatrix/release-critical.json`](../../test/qamatrix/release-critical.json)
задаёт точный, проверяемый набор: все **59 уже рассмотренных CLI/MCP операций**,
их provider-статусы, важные входы, четыре именованных исключения и публичные
Go-тесты. Это зафиксированный список для текущего выпуска; изменение списка
требует отдельного review причин и сохранения явного остатка каталога.
Runner проверяет SHA-256 байтов профиля относительно утверждённого значения
в `scripts/qa_matrix.py` и отклоняет изменение профиля, в том числе
одновременное сужение contracts и выбранных операций либо удаление обязательных
публичных тестов. Изменение утверждённого значения требует явного review
решения для выпуска; текущие contracts и provider-статусы также проверяются
при прогоне.

## Что входит в критичный проход

| Область | Требуемое наблюдаемое доказательство |
| --- | --- |
| Авторизация | Публичные ответы 401/403, типизированная ошибка и подсказка CLI/MCP; секреты не попадают в вывод. |
| Списки | Пагинация и предел выдачи проверены по ожидаемым запросам, границам и результатам. |
| CLI | JSON, обычный вывод и ошибки проверены по публичной команде и независимо ожидаемому результату. |
| Изменения состояния | Создание/чтение/изменение/удаление проверены через запрос и наблюдаемый эффект; отказ в удалении сохраняет ресурс. |
| Pull request merge | Ручной merge проверен по Cloud и Server/DC контрактам и публичному CLI. Четыре флага ниже остаются явно отложенными. |
| MCP | `initialize`, `tools/list`, входная схема, `tools/call`, JSON-RPC envelope, успех и ошибка проверены по публичному протоколу. |
| Commit files | Публичный CLI и контракт проверяют текущий путь адаптера для commit hash и JSON/JQ. Исторический сбой процесса на прежнем репозитории этим тестом не воспроизведён и не объяснён; запуск бинаря-кандидата остаётся отдельной проверкой артефакта. |
| Cloud lifecycle | Live-прогон на финальном SHA должен подтвердить создание, чтение и независимую проверку cleanup. Hermetic-сценарий не доказывает этот live-эффект. |

Для каждой выбранной поддерживаемой строки нужны публичные success/error
сценарии с осмысленными проверками входа, вывода и эффекта по применимости.
Неподдерживаемый provider требует публичного отказа и рассмотренной причины;
локальная операция — локального success/error доказательства. Имена тестов и
важные входы проверяются машинным профилем, но само имя теста или метка
сценария не заменяет проверку его assertions.

## Четыре отложенных входа

| Provider и операция | Флаг | Неопределённость |
| --- | --- | --- |
| Cloud CLI PR merge | `--auto` | Документированный контракт Cloud auto-merge ещё не подтверждён. |
| Cloud CLI PR merge | `--auto-off` | Документированный контракт Cloud auto-merge ещё не подтверждён. |
| Cloud CLI PR merge | `--rebase` | Документированный Cloud режим стратегии ещё не подтверждён. |
| Server/DC CLI PR merge | `--rebase` | Точное wire-значение стратегии Server/DC ещё не подтверждено. |

Эти флаги не объявляются протестированными. Их исключения ограничены именно
этими важными входами и сохраняются в полном backlog. Синтетический HTTP
ответ не подтверждает поведение живого provider; исключение не разрешает
обойти обнаруженный дефект ручного merge или другой проверенной операции.

## Как оценивать результат

1. Запустить `make qa-matrix` для полного hermetic `./...` прогона с race,
   shuffle, coverage и сохранёнными событиями, либо использовать единый
   release-прогон. Проверить `report.md` и `report.json`.
2. Запустить `make qa-critical-check`. Gate повторно проверяет исходный
   fingerprint, контракты, test events и hashes, затем выбранные пары и
   обязательные публичные тесты. Пропуск, ошибка, отсутствие доказательства
   или устаревший результат дают отказ.
3. Опубликовать полный отчёт рядом с критичным результатом: каждая
   незавершённая строка каталога остаётся явным backlog. Для исчерпывающего
   завершения использовать `make qa-matrix-check`.

[Срез Round 2](2026-10-19-cli-mcp-matrix-round2.md) — отдельное прежнее
измерение, также с **123/1165** полными строками и **1042** незавершёнными.
Одинаковые числа не делают старый отчёт доказательством нового gate. В старом
срезе были рассмотрены 59 операций и 125 строк, из которых 123 были полными;
четыре исключения выше относятся к двум начатым merge-парам. Новый локальный
gate прошёл с этими точными исключениями до его усиления. Полный каталог и его пробелы
сохраняются, даже когда критичный gate прошёл.

Критичный pass — только локальный Stage 2 gate. Для выпуска ещё требуются
обязательный CI и Cloud live acceptance **на том же финальном SHA** с
provisioning, readback и независимой проверкой cleanup; запуск native
артефактов, npm install и Docker MCP entrypoint; SHA и digest проверенных
байтов с доказанной связью с публикацией; исправные Release Please credentials.
Отложенный live Server/DC требует точной пометки **«DC не проверен live»** в
QA-отчёте и release notes и не оправдывает найденный DC-регресс.
