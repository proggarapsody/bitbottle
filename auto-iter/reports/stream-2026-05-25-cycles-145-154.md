## Confirmed structural findings (evidence-backed)

### Finding 1: design-judge race no longer producing follow-up PRs

**Measurement**: 0 of 10 cycles in this stream produced a post-merge
follow-up PR for a missed DJ BLOCKER. Compared to 2 of 8 in cycles
135–144 (cycles 139, 143).

Three cycles ran with DJ WARNs (148, 152, 154) but no BLOCKERs landed on
`main`. Cycles 149–151 produced DJ PASS-all-7. The §3.6 ordering change
recommended in the previous report appears to have closed the gap; no
auto-merge-vs-DJ race is visible in this batch.

**Caveat**: n=10 with 0 events is not the same as proving the failure
mode is gone. The right next observation is the *first* BLOCKER landing
on main — if that doesn't happen within the next 20 cycles, the fix is
robust.

### Finding 2: stub-completeness gap on interface extension (cycle 153)

**Measurement**: 1 of 10 cycles had a CI failure traceable to a fake-
client missing a newly-required method (`fakePipelineClient` lacked
`RerunPipeline` after `PipelineClient` gained the method). The TDD red
test passed locally because the new method had a happy-path stub; CI
failed on the *other* tests in the same package that constructed the
fake for unrelated cases.

**Inferred mechanism**: when extending an interface used by a hand-rolled
fake, the TDD subagent adds only the method it's writing the test for.
Other test files in the package break silently because they construct
the same fake type by literal.

**Fix scope**: small. Either generate fakes from interface (codegen), or
add a `var _ PipelineClient = (*fakePipelineClient)(nil)` compile-time
assertion in every package that hand-rolls a fake. The assertion form
catches this at build time, not test time, and is a one-line change per
fake.

### Finding 3: BACKLOG-flip-missed-worktree is recurring (cycle 147)

**Measurement**: cycle 147 needed a standalone `chore` PR #507 to flip
BACKLOG status. The cycle's feat commit landed on main without the flip
because the worktree's BACKLOG.md hadn't been re-pulled after the prior
cycle's release-please merge.

This is the same anti-pattern called out in the project memory ("BACKLOG
status flip belongs in the feat commit, never a separate chore PR"). It
recurred here despite being documented.

**Inferred fix scope**: a preflight check on cycle start that diffs
`worktree:BACKLOG.md` vs `origin/main:BACKLOG.md` and refuses to
proceed if they disagree on already-shipped scopes. ~10 lines of bash
in `auto-iter/scripts/preflight.sh`.

## Observations that are NOT yet patterns

- **GitGuardian false-positive on test fixtures** (cycle 147): the
  literal `s3cr3t` in a fixture tripped GitGuardian. Renamed locally and
  pushed; no recurrence. n=1. Worth a `.gitguardian.yml` ignore entry
  only if it happens again.
- **gofmt drift on long cycles** (cycle 154, 12 steps, 30m): a gofmt
  fix was needed mid-merge. The pre-push gate caught it before merge,
  but only after a re-push. n=1; could be that long cycles allow more
  human/agent file edits without running `make fmt`.
- **Cloud-claim-drift WARN** (cycle 152): DJ flagged that PR-SETTINGS
  doc claimed Cloud parity where the Cloud endpoint shape differs. WARN,
  not BLOCKER. n=1 — monitor whether DJ keeps catching this category
  reliably.

## Recommendations for future streams

Ordered by evidence strength + fix size:

1. **Interface-extension fake-completeness assertion** *(n=1, very small
   fix)* — add `var _ Interface = (*fakeImpl)(nil)` compile-time
   assertions in every test package that hand-rolls a fake of a domain
   interface. One line per fake; catches cycle-153-class failures at
   build time, not test time.
2. **BACKLOG-flip preflight check** *(n=2 across two streams, small
   fix)* — diff `worktree:BACKLOG.md` vs `origin/main:BACKLOG.md` at
   cycle start and refuse to proceed if status flags disagree on
   already-shipped scopes. Stops the standalone-chore-PR anti-pattern.
3. **Token-row emission** *(0/10 cycles have token data)* — the
   previous report flagged this for a subset of cycles; this stream is
   uniformly missing it. Without token data, stream-vs-historical cost
   comparisons remain impossible.
4. **DJ run on every cycle, including fast and dual-scope** *(3/10
   missing)* — even read-only or doc-only cycles should produce a DJ
   record so the "BLOCKER rate" denominator is consistent.
5. **`make fmt` in pre-push hook** *(n=1 — monitor)* — gofmt drift on
   cycle 154 was a single occurrence; promote to a fix only if it
   recurs in the next stream.

## Bottom line

What this stream demonstrably shows:

- 10/10 shipped, 0 follow-up PRs for missed BLOCKERs — the post-merge
  race called out in the previous report does not recur in this batch.
- Step-level instrumentation is now consistent (every cycle has 6–12
  step rows), closing one of the previous data-quality gaps.
- Three distinct CI-failure modes appeared, all caught pre-merge: secret
  scanner FP, hand-rolled fake gap on interface extension, gofmt drift.
  All are small fixes; the fake-gap one has the strongest signal.
- DJ is now producing PASS / SHIP-with-WARN / BLOCKER as three distinct
  categories with usable granularity (3 PASS, 4 WARN, 0 BLOCKER).

What it does not demonstrate:

- That cycle cost has dropped — no token rows were emitted this stream.
- That the auto-merge ordering fix is robust at scale — 0 events in 10
  cycles is consistent with both "fix works" and "no BLOCKERs happened
  to arrive". Next 20 cycles will tell.
- That the BACKLOG-flip and stub-completeness issues are rare — both
  have n=1 here, but the BACKLOG-flip one matches a pattern already in
  project memory, so it should be treated as recurring, not novel.
