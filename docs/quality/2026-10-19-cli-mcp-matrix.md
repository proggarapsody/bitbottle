## Доказательство

Локальный `make qa-matrix QA_MATRIX_DIR=/tmp/bitbottle-stage2-final` прошёл на этой рабочей ревизии с race/shuffle без кеша: Go exit 0, 0 fail, 0 пропущенных обязательных тестов. Live acceptance явно `not_run` (1 opt-in skip); 3 пакета без тестов учтены отдельно. Записано **86 passing-сценариев** (44 CLI + 42 MCP), проверено **30/1158 provider pairs**, включая **30/44** пар пилота. Остаток: **1114** пар без reviewed-классификации и **14** начатых пар с пробелами эффекта/важных входов; всего **1128 incomplete**. Это объём доказательств, а не процент качества продукта.

`make qa-matrix-check QA_MATRIX_DIR=/tmp/bitbottle-stage2-final` ожидаемо завершился exit 1: `matrix incomplete: 1128 provider pairs`. Целостность и соответствие исходникам пройдены; отказ вызван именно неполной матрицей. `make lint`, shell-инструменты через `make test-scripts`, 21 Python-регрессия runner и actionlint прошли. Raw events, manifest, catalog и report хранятся в указанной локальной директории; CI публикует такой же набор как artifact `qa-matrix-<run_id>-<attempt>`. Проверки конкретного remote SHA доступны в PR этой ветки.

Каталог содержит 384 узла CLI, 298 запускаемых CLI-операций и 281 MCP-инструмент: всего 579 операций, исходно 1158 пар с Server/Cloud. Глобальный `--version` проверяется отдельно через приложение. У 276 MCP-инструментов отсутствует декларация backend; отсутствие не означает поддержку. Явно проверенный контракт применимости хранится отдельно от деклараций.

- [Публичные CLI-сценарии](../../test/contract/public_matrix_integration_test.go): настоящее дерево команд и Cloud/Server HTTP adapters, независимые ожидания method/path/query/body, результат, ошибки, пагинация и чтение после записи.
- [Публичные MCP-сценарии](../../pkg/cmd/mcp/public_matrix_test.go): настоящий SDK и отдельный stdio-процесс, синтетические stateful backend-клиенты с корректными optional interfaces. Это MCP/domain-контракт, а не проверка провайдера по HTTP или live.
- [Проверенные требования](../../test/qamatrix/contracts.json) пока описывают 22 операции. Остальные строки остаются unknown. Важные параметры проверяются по фактическим сценариям; наличие флага в каталоге не означает проверку его поведения.
- [Runner](../../scripts/qa_matrix.py) связывает записи с pass конкретного Go-теста и пакета, сохраняет исходные события и fingerprint исходников/фикстур. Подмена, устаревший результат, неуспешный/пропущенный обязательный тест и узкий package scope не проходят строгую проверку. Метки сами по себе не доказывают силу assertions: тесты проходят отдельное review.
- В hermetic-прогоне live acceptance явно `not_run`; этот пропуск не является Cloud/DC pass. Пакеты без тестов перечислены отдельно.

## Исправленные регрессии

1. Server/DC `UpdatePR` отправлял частичный PUT без refs/reviewers. Теперь сохраняется полный полученный объект и меняются только запрошенные поля. Строгая HTTP-фикстура и публичный CLI-вызов воспроизвели ошибку до исправления и прошли после него ([регрессия adapter](../../api/server/pr_update_fullobject_test.go)). Это hermetic-доказательство, **DC не проверен live**.
2. Пять MCP issue-ID инструментов (`get_issue`, `close_issue`, `update_issue`, `reopen_issue`, `assign_issue`) сообщали «missing id» для строкового ID. Теперь возвращается типизированная `arg.invalid_type`; регрессия воспроизведена через SDK/stdio.
3. Review самого runner выявил обходы через reason-only `not_applicable` и объединение неполных assertions разных сценариев. Оба обхода закрыты отдельными Python-регрессиями: outcome должен иметь один полный passing-сценарий, а произвольная причина неприменимости не даёт pass.
